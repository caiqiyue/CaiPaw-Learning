# learning-notes/ —— 学习笔记（★ 本项目真正的产物）

> `docs/核心宗旨.md` §9：
> **不是为了做出一个 Agent，是为了在做出它的每一步里，看懂每一行。**
>
> 代码是副产品，**这里才是主产物**。
>
> 📌 本目录**必须入库**（见 `.gitignore` §6.4）。它是这个项目区别于「把 QwenPaw 抄一遍」的证据。

## 目录分工

```text
learning-notes/   ← 你在这里。文字笔记（.md）
assets/           ← 笔记里引用的图片
```

两者是配套的：笔记里贴截图 / 架构图 / trace 截图，图放 `assets/`，笔记用相对路径引用。

## 命名规范

```text
learning-notes/step-NNN-<短横线小写英文slug>.md
```

- `NNN` —— **全局三位序号**，从 `001` 开始，跨模块连续递增（**不按模块重新计数**）
- slug —— 用英文小写 + 短横线，一眼看出这步在干嘛

例：

```text
learning-notes/step-001-first-llm-call.md
learning-notes/step-002-langchain-abstraction.md
learning-notes/step-003-first-tool.md
```

**为什么全局连续**：这样 `ls learning-notes/` 就是一条完整的学习时间线，
不用在脑子里做「M03 的第 4 步等于全局第几步」的换算。

## 贴图怎么放

图片统一放 `assets/`，笔记里用**相对路径**引用：

```markdown
![第一次 LLM 调用的响应结构](../assets/step-001-response-shape.png)
```

图片命名跟着笔记走（`assets/<笔记同名>-<描述>.<ext>`），详细规则见 `assets/README.md`。

> ⚠️ 图片**也要入库**，否则笔记里的图全挂。但也别无脑塞：
> 别放几十 MB 的截图，别放模型权重 / 数据集（那些 `.gitignore` §4 已经挡掉了）。

## 每篇笔记的必备 5 段（对应 L3 + L4 + 学习验证）

```markdown
# step-NNN · <这步做了什么>

- **所属模块**：M0x（`docs/任务清单-粗粒度.md`）
- **feature**：`a0x`
- **日期**：YYYY-MM-DD

## 1. 这步新增了什么（大白话）
> 不许出现类名 / 函数名。讲给一个不懂编程的人听。

## 2. 关键代码在哪几行、为什么这么写
> 贴 3~10 行核心代码 + 逐行说明「为什么是这句，不是别的写法」。

## 3. ★ 认知落差（没有落差 = 学得太浅）
> **我原本以为**：……
> **实际是**：……
> **为什么会想错**：……

## 4. ★ 自测（L4：自己动手改一处）
> **改了什么**：……
> **改之前我的预测**：……
> **实际结果**：……
> **预测对了吗 / 差在哪**：……

## 5. 与 QwenPaw 的对照（涉及 QwenPaw 时必写，L6）

> ⚠️ **L7 提醒**：这一段是「**写的时候**对照」（L6）。
> 而「**拆的时候**先读源码」（L7）发生在更早 —— 在 `docs/进度/M0N-*.md` §2。
> 两段都要有：**§2 定方向，这里是逐条的差异**。
> **QwenPaw 怎么做的**：……
> **我们怎么做的**：……
> **为什么不同 / 我们简化了什么**：……
```

## 三条纪律

1. **不许事后补**。写完代码顺手写，不要攒到最后一起编 —— 编出来的笔记没有「落差」，全是总结。
2. **第 3、4 段不许空**。空的说明这步**太简单**（可以走快点）或**太复杂**（应该拆开）。
3. **第 5 段是本项目存在的理由**。不复盘差异，就只是「又写了一遍」，不是「重构」。
